## Goal

Snapping must live in `@modeling-kit/snapping` and be reusable. `KnifeTool.previewPoint` must call that service instead of only `snapKnifePoint` from mesh.

## Existing APIs to reuse

- `snapToGrid`, `snapIncrement`, `snapAngle`, `snapToPoints` in `packages/snapping/src/snap.ts`
- `HalfEdgeMesh` queries; do **not** copy `snapKnifePoint` logic into a third place — either wrap it behind `SnapQuery` (snapping may depend on mesh) or extract shared math into snapping and have knife-planner call snapping (mesh **must not** import snapping).

Preferred: snapping depends on `mesh`; `querySnap(mesh, point, options)` returns `SnapResult`. KnifeTool calls `querySnap`. Leave `snapKnifePoint` as a deprecated wrapper that calls the same algorithm **or** keep it as implementation used by `querySnap` by moving the function into snapping.

If moving would force mesh → snapping, **do not**. Keep geometric snap in snapping; KnifeTool builds candidates (vertex positions, edge midpoints, face centroids) and uses `snapToPoints` + new `snapToEdge` / `snapToClosestOnSegment`.

## Allowed files

- `packages/snapping/src/snap.ts`
- `packages/snapping/src/query.ts` (new)
- `packages/snapping/src/index.ts`
- `packages/snapping/package.json` (allowed dependencies: `@modeling-kit/mesh` and `@modeling-kit/core`)
- `packages/snapping/tsconfig.json` (paths)
- `packages/snapping/tests/snapping.test.ts`
- `packages/tools/src/knife-tool.ts` (call SnapQuery only)
- `packages/tools/tests/knife.test.ts` (assert snapped point still works)

## Forbidden

mesh operator files, commands, three-adapter, new npm deps besides workspace mesh/core.

## Acceptance tests

1. Grid + vertex: point near a cube vertex snaps to vertex when vertex priority > grid.
2. Midpoint: point near an edge midpoint snaps with `targetType: "midpoint"`.
3. Face: point near a face centroid snaps with `targetType: "face"`.
4. KnifeTool.previewPoint with mesh uses the snapping package (test still passes existing knife snap cases).
5. Empty mesh / radius 0: `matched: false`.
